# 0.6.0 UNKNOWN 链路补齐与最终验收

验证日期：2026-10-15。本次扫描器工程验收通过；三个目标应用仍存在 UNKNOWN，未完成应用安全验证。UNKNOWN 总数没有减少，本轮改善的是路径覆盖、原因定位与复核任务的可执行性。

版本 `0.6.0`，规则集 `java-python-guardrail-v7`，报告结构 `1.5`。发行模块为 `compat/`，不是仓库根目录的 Java 21 参考实现。

## 本轮实现

| 能力 | 实现及保持的边界 |
| --- | --- |
| Java 条件路径 | 在完整赋值、返回等可保持执行顺序的位置展开条件表达式；隐式虚调用保留候选，不据此确认实际注入实现 |
| Python 流式来源 | 简单 `for` 保留零次与一次代表路径，跟踪流元素来源；不把整个流的校验证明赋给每个元素，不用一次迭代证明全部安全 |
| 真实输出边界 | 外部 v2 合同支持参数条件 `when`，区分内容和状态事件；未知条件保守处理，不由事件构造推断网络已经发送 |
| 值与判定一致性 | 布尔条件使用实际计算结果；脱敏转换清除未被合同保证保留的旧常量与字段，防止根据转换前常量跳过真实输出 |
| UNKNOWN 明细 | 保留逐位置原因和其他未评估路径；已定位的候选或失败放行 Guard 调用单列复核，不冒充已证明的输出违规 |
| 复核动作 | 区分补映射、扩分析、确认范围、运行负测、定位证据；包含负责角色、具体位置与所需证据 |
| 报告验收 | JSON、Markdown、SARIF 复核字段一致；同一规则多条评估按各自正文核对，避免误读第一条同名规则 |

新增实现与合成回归均采用通用语义；引擎中没有三个项目专属的类名、路径或场景分支。真实 API 合同在仓库外维护，仍需人工审查。没有修改三个目标应用来让扫描结果通过。

## 剩余重点与人工证据

| 项目 | 扫描或映射仍需补齐 | 必须由应用、业务或安全人员确认 |
| --- | --- | --- |
| CodeBuddy | 多网关实现、对象构造、字段投影与回调的完整值流；跨函数会话主体绑定 | 认证入口和客户端身份回退的实际部署行为；已定位检查的失败放行语义；会话/消息归属；知识内容是公开模板还是受限资料 |
| wm-sales-atlas-analysis | 控制器身份到服务参数的跨函数传播；网关、循环和流片段关系；业务事实、适当性及工具边界映射 | 所有权断言与并发首次绑定是否有效；是否实际启用文档检索及其适用范围；事件封装后的实际输出时序 |
| 蒸馏小可乐 | 流式生成与最终校验的跨函数关系；会话、缓存主体及混合检索约束映射 | 质量校验是否承担安全职责；首个片段释放前是否已审核；拒绝、异常、超时与回退行为；会话与缓存共享规则；向量/BM25/重排/缓存的文档授权与撤权一致性 |

RAG 源码可定位“先逐片段输出、后汇总校验”的顺序，但质量校验是否构成安全 Guard、流内容是否受其他控制约束尚未建立，不能仅据该顺序宣布银行 Guard 规则已完成违规判定。CodeBuddy 已定位的失败放行检查也与尚未打通的最终输出路径分开报告。

人工确认应交付证据，而非只勾选确认：

1. **身份与隔离**：服务端主体来源、身份覆盖规则、会话与资源所有权，以及跨用户、跨租户、并发访问的负测结果。负责角色：应用、身份平台与测试负责人。
2. **文档与数据范围**：公开/私有/租户共享分类，授权与撤销规则，上游服务或数据库过滤依据，以及检索、重排、缓存中的一致性。负责角色：业务与数据权限负责人。
3. **Guard 失败阻断**：控制实现和依赖版本的审查依据，拒绝、异常、超时和回退测试；记录审核前是否已经释放原文、首个流片段或工具副作用。负责角色：应用测试与安全负责人。
4. **场景适用性**：确认真实启用的业务与调用入口；未找到映射不能自动判定规则不适用，尤其是尚未定位真实检索入口的场景。负责角色：应用与业务负责人。

补 API 映射、解析接收者、扩展跨函数分析属于研发工作，不应全部转交业务人工背书。报告中 `reviewActions` 将这些动作与必须人工提供业务/运行证据的动作分开。
