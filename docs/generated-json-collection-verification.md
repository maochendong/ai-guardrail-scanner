# 0.10.0 生成访问器、动态 JSON 与集合关联验收

版本 `0.10.0`，规则集 `java-python-guardrail-v11`，报告结构 `1.9`。本轮扩展通用结构分析，沿用现有外部语义合同；不以目标项目名、函数名含义或字段名称授予安全结论。

## 实现与边界

| 能力 | 已实现 | 仍需保留的限制 |
| --- | --- | --- |
| Lombok 默认访问器 | 识别真实注解、字段、显式方法与配置查找边界；只对确定接收者和可确认的默认生成语义建立摘要 | 根外配置、注解处理和实际生成代码需要独立证据；自定义 Accessors、覆盖、初始化副作用及不确定分派不套用默认语义 |
| Python 动态 JSON | 标准解析结果拥有独立身份；关联常量键、可解析键别名、嵌套字段及源码有界整数下标；保留异常路径 | 未知键类型、解析钩子和同名模块不获得精确摘要；解析出的数字暂不恢复精确整数类型 |
| 默认 Jackson 树 | 源码证明使用默认 ObjectMapper 时，区分 `get`、`path`、`has`、`asText` 的字段及缺失语义 | 注入/配置/逃逸的 mapper 不适用；数值节点文本不借内部数字格式推定字面值；节点强制转换仍保留异常 |
| 值修改与别名 | 同一字段的不同读取、默认值候选和嵌套变更撤销旧校验及可能失效的结构 | 可能别名不等于值相等；未知副作用不能借再次读取恢复旧证明 |
| 集合逐项关系 | 独立记录检查、追加与输出三处位置及元素、主体、判定和集合绑定；三格式保留复核动作 | 代表性迭代不是全量证明；未知 Map 复制只表示派生关系；每条集合复核保持 UNKNOWN |

集合关系当前附在业务规则包中。通用 Guard/检索规则继续复用主值流已定位的事实，不凭集合的 release 合同推定其来自模型。新结构语义也不会自动获得首包时序证明，未建模动态键与生成配置在时序分析中保守处理。

回归覆盖同名注解、显式覆盖、配置外溢、错误字段、不同对象、复合判定缺项、候选控制、失败开放、嵌套与默认值别名变更、异常分支释放、数值文本及集合错误元素。两个旧断言按新增支持调整：Python 混合脱敏/原文列表可识别为违反，Java 未支持数组仍为 UNKNOWN；动态下标进入中间表示，但运行时未知键仍不能成为精确字段。

## 三项目的实际变化

- **CodeBuddy**：可定位生成方法相关的不确定性；一条业务事实规则由暂不支持改为证据不足。生成配置及实际构建语义未确认，相关字段不能获得安全资格，父级仍为 UNKNOWN。
- **WM**：新增逐项检查、加入集合与同一集合返回的证据；可见的是派生元素，主体与完整决策绑定尚未建立，全量覆盖继续 UNKNOWN。迭代范围更明确后，一条身份规则的主分类变为暂不支持；分类变化不代表新增漏洞。两条旧 `ORDER_UNRESOLVED` 时序位置不再出现在本轮有界输出中，前后均有时序截断，不能视为 UNKNOWN 已消除；相应输出的主值流评估仍为 UNKNOWN。
- **RAG**：本轮逐位置摘要与 0.9.0 相同，未减少 UNKNOWN。新增动态 JSON 能力通过通用回归验证，不能据此声称该项目的控制资格、权限或流式链路已完整建立。

最终本地 `final-review/` 包含 `unknown-review.md/json`、`manual-review.md/json`、`technical-followups.md/json` 与 `comparison.json`。共有 84 条父级 UNKNOWN，按项目、规则、动作与负责人合并后的人工报告动作 19 组、研发动作 127 组，另列 9 项业务/部署事项；这些分组不等于漏洞数，也不与 UNKNOWN 一一对应。

## 人工确认与研发后续

必须人工提供的证据包括：业务适用范围，认证与租户的可信注入，文档/会话/缓存的公开或受限分类及撤权，Guard 的安全职责和失败策略，业务适当性与二次确认，工具及出站白名单，以及部署中的异常、超时、取消、跨租户和客户端首包负测。生成代码受根外配置影响时，还需构建负责人提供有效配置、注解处理状态和可审查生成结果。

自定义生成方法、集合全量证明、动态调用与异步时序仍是研发能力缺口，不能用人工口头确认替代。逐位置 UNKNOWN、人工事项和研发清单分别保存在本地验收目录，公开仓库仅保留脱敏汇总。
