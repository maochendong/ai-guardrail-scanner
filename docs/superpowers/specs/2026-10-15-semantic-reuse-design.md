# 外部语义复用与缺映射补齐设计

本轮是用户已确认的规则包与通用语义扩展：补齐可由真实源码支持的映射、保持泛化和原生 JDK 7/8、回归及三个项目复验后推送。演示材料第 9 页同时细化，最终措辞与实际实现一致。

## 边界与选择

9 项缺映射指 9 条评估没有解析到对应 sink，不意味着存在 9 个只需登记的安全控制。逐项核对实际接口及业务适用性；不存在的业务接口、未获资格的控制、运行环境假设不通过 JSON 虚构。真实合同与目标报告留在公开仓库之外。

采用一次共享语义分析、按含义消费证据的方案。继续复用现有语言适配、BusinessFlow 与有界解释器；通用分析保留原有框架检查，通过明确规则对应关系消费同值校验、释放、检索等语义证据。相比在两种语言各写一套解释器，这避免失败语义与值流分叉；相比把专项结论直接覆盖通用结果，这保留了规则适用范围与未覆盖路径。

允许 generic profile 显式加载操作员合同，仍不输出未选择的 BANK 规则。源摘要不匹配、候选资格、未解决绑定、预算截断均不得提升为安全结论。按位置和语言关联证据，已有违反不可被新映射降级。资源访问不等同会话，数据出站不等同日志，工具能力不等同 schema 校验。只在真正同义的规则处复用，暂未建立对应关系的规则继续说明边界。

## 验收标准

1. 每项原缺映射都有真实边界与映射结果，或明确剩余阻碍和负责人；不要求人为归零。
2. Java/Python 合成反例覆盖正确拒绝、忽略结果、错值、先释放、候选、失败放行、摘要过期与无关映射。
3. 无合同行为兼容；generic 不泄漏 BANK 评估；混合语言与各调用点的证据相互隔离。
4. 真实 JDK 7 编译，JDK 7/8 对同一最终 JAR 运行全量回归与三项目 MCP、JSON/Markdown/SARIF 验证。
5. 人工确认与研发补齐分别列出，目标源码未修改。公开提交不包含私有 API 合同、扫描结果与演示录屏。
6. 新版本安装至本地 Codex，核对制品及新进程报告一致，再推送并检查远端提交。
