# 生成访问器、动态 JSON 与集合校验关联

用户已授权沿用通用规则、原生 JDK 7/8 与三项目复验流程继续开发。基线为 0.9.0 / 337bac1；成功标准是补足有源码依据的关系，不预设 84 条 UNKNOWN 必须减少。

## 方法选择

扩展现有 BusinessFlow 与受限静态解释器，避免执行目标构建或注解处理器。只增加外部合同无法替代的结构语义；不按项目、字段名称或控制函数名称猜测安全属性。相比仅补合同，可复用源码细节；相比无界堆分析，保持已有资源边界。

1. Lombok：解析真实注解来源、字段、默认方法规则及可见配置；显式覆盖、继承、Accessors、自定义配置等无法确认的情况保守处理。配置向上查找仍限定于授权根。无法证明默认配置时，候选字段关系带生成资格未确认原因，不能授予同值保护。只对精确构造接收者或不可覆写类生成摘要。
2. JSON：标准库解析后的运行时内容可以具有可追踪的字段身份，但解析输入、根对象和字段是不同值，不能继承输入的 Guard 决策。常量键、可解析键别名和有界数组投影可以建模；未知键类型、自定义解码、变异及异常路径保持保守。动态结构不提供业务正确性、身份可信度或完整集合覆盖证据。
3. 集合：增加逐项检查、加入集合和返回集合之间的源码关系证据，明确同一元素、主体、决策和输出集合是否能关联。一次代表性迭代不能证明所有项；未完成归纳证明的集合关系独立保留 UNKNOWN，不提高父级结论。

## 验收与交付

使用通用命名正反例覆盖配置覆盖、错误字段、键变更、不同对象、异常释放、未检查项加入和集合逃逸；保留原有 soundness 回归。静态分析不运行三项目构建，源码与配置不变。对比前后逐位置证据与原因，人工运行/业务资格事项和研发缺口分别导出。通过原生 Java 7 编译、Java 7/8 全量测试与三项目 MCP 复验后，推送仅含通用实现及脱敏说明的 GitHub 提交。
