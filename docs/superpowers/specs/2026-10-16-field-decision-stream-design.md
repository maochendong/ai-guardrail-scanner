# 字段值流、复合判定与流式 Guard 关联

用户已明确要求继续实现上一轮列出的三组研发缺口，保留人工事项、规则泛化和原生 JDK 7/8，并复验三个项目后推送。基线为 0.8.0 的 84 条 UNKNOWN；本轮成功标准是消除有源码依据的分析缺口，不预设 UNKNOWN 必须下降或应用必须通过。

## 选择与边界

沿用现有 ANTLR → BusinessFlow → 有界值流解释器。对源码明确的 DTO 构造与访问、JDK Map 常量键及 Python 已知字典建立字段关系；不按类名、方法名或目标项目猜测安全属性。无法获得生成访问器实现的 Lombok 路径、动态 JSON 内容及未知 mutation 继续作为研发缺口。相比只添加私有合同，这能复用源码；相比无界堆分析，仍保持资源与验证边界。

外部结果对象的复合控制使用 v2 合同兼容扩展：`decision.all` 声明最多 8 个 `{symbol,arg,accept}` 叶子，仅支持合取。必须是同一次检查返回的同一个对象，所有叶子在当前路径和有效时期均满足；错误对象、遗漏叶子、反向分支、OR 放行、修改与异常不能拼接保护。旧单叶 `decision` 含义不变。实际服务的资格、失败策略与业务适用性不因表达式可分析而提高。

流式分析补充释放片段到后续检查输入的显式值依赖。`checked-value-derived-from-release` 仅说明源码依赖关系，不等于内容相同、所有片段完整或前置安全保护；后置聚合检查仍为先释放后检查。异步、网络送达及外部控制实现保持原边界。

## 验收

- 用通用名称的合成正反例验证字段、对象、条件、修改、顺序与截断；不修改三项目源码。
- 保留原有 VIOLATED 与未覆盖 UNKNOWN；逐位置比较投影原因和时序事实，区分新增证据与关闭评估。
- JSON/Markdown/SARIF 保留新关系与限制，人工只列范围、职责、部署和运行证据，研发任务另列。
- 真实 JDK 7 编译，同一成品 JAR 在真实 JDK 7/8 全量测试与三项目 MCP 扫描；安装至本地 Codex 后比较新进程稳定报告。
- 公开提交只包含通用实现、合成测试及脱敏结论；私有合同、目标源码和报告保留本地。
