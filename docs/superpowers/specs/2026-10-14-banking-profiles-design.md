# 银行规则包设计（已按用户指令进入实现）

## 范围与信任边界

保留现有 L1–L7、Java/Python 离线扫描、JDK 7/8 原生运行和五个 MCP 工具。增加由启动方选择的 `bank-common`、`bank-customer`、`bank-internal`、`bank-all` 配置；后两个场景分别对应客户服务/理财销售辅助、行内知识库/办公研发助手。默认 `generic` 保持原有规则选择。目标应用、模型及其构建脚本均不执行。

银行配置由 CLI/MCP 启动参数指定。目标仓库里的文件、注释与 MCP 请求不能覆盖配置。可选的外部 JSON 合同映射精确指定全限定调用符号、参数位置和返回值语义；不根据类名、业务词或项目名称推测身份、敏感性或 Guard 成效。合同是操作员声明的假设，不证明被调用实现本身正确。缺少映射保持 UNKNOWN。

## 规则包

共性：BANK-DATA-001 检查已分类敏感值在出站前使用脱敏结果；BANK-IAM-001 检查资源访问和检索绑定可信身份及同一资源的授权结果；BANK-GUARD-001 检查输出前使用 Guard 结果并在拒绝/异常路径停止释放。

客销：BANK-CUST-001 检查推荐前事实/时效校验；BANK-CUST-002 检查绑定客户身份和推荐对象的适当性校验。

行内：BANK-INTERNAL-001 检查检索前文档 ACL；BANK-INTERNAL-002 检查工具参数和能力授权。模型注册审批、知识版本治理、完整审计制度及运行时超时/并发验证仍须由外部控制与人工验收完成；本版不声称静态源码证明这些制度。

## 静态语义

两种语法适配器输出共同的局部控制/值流 IR：函数、赋值、调用、布尔分支、返回/抛出、try/catch/finally。有界路径解释器追踪同一值的来源、转换、检查及释放。检查仅在接受分支对相同参数生效；无视返回值、重赋值、先输出后检查和异常回退释放均不能借检查调用获得已覆盖结论。

动态调用、循环、跨函数/字段状态等未建模语义必须降级为 UNKNOWN；路径/节点上限产生诊断，不能删去缺口后得出通过。证据只输出受控描述和相对路径行号，不复制源码或合同内容。

## 输出与验收

报告单列 profile、合同摘要、规则版本、gateDecision（BLOCK/REVIEW）。静态扫描始终 `complete=false`、`securityVerified=false`，本版不输出 ALLOW。确认违反为 BLOCK，其余 REVIEW。JSON/Markdown/SARIF、MCP 状态和 CLI 退出码保持一致。

每条新增规则须有合成正反例及不确定例，特别覆盖改名、遮蔽、错误参数、反向布尔条件、异常回退和预算。真实 JDK 7/8 分别运行测试与 stdio MCP；三个用户项目只作只读回归，无法代替银行规则合成验收。公开仓库只发布通用实现、合成合同样例和汇总验证文档。
