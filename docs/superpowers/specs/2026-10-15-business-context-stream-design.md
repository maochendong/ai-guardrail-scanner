# 业务语义分析、跨函数身份与首包时序

用户已明确要求将 Bank 类名改为 Business，并继续实现此前提出的受限跨函数与流式时序能力，完成 JDK 7/8、三个项目和 GitHub 交付。本设计沿用已确认的外部语义合同与有界分析方向。

## 范围与取舍

1. 兼容发行模块的 `Bank*` 类与测试统一改为 `Business*`。规则 ID、历史 `bank-*` profile 和启动参数保留兼容，避免把类名调整扩展为破坏现有接入的协议迁移。
2. 使用调用上下文相关的有界函数执行传播实际参数、返回值及身份来源。采用唯一源码方法身份区分同参数数量重载；候选虚调用只记录候选上下文，不授予确定控制。递归、深度预算、未知修改和无法确定的异常继续保守处理。
3. 每个函数的独立入口仍保留，某个受信调用者不能把同一被调函数的所有入口变成受信。正常返回之间只保留一致的证据，不允许某分支上的校验覆盖另一分支。
4. 首包时序作为独立证据：记录释放早于映射检查、同值成功检查早于释放或顺序未决。循环只观察零次与一次代表路径，不证明所有迭代；本地 yield 不等于客户端已收到网络数据。
5. 候选质量校验可提供相对顺序事实，不升级为安全 Guard。确认前置审核必须同时满足同值绑定、受信控制及失败阻断语义；输入检查和整体流检查不能替代片段检查。
6. 采用新的报告上下文明细保存事实，不改变未建立的安全处置。必须人工确认的身份部署、资源范围、控制职责和运行负测，与解析/映射缺口继续分开。

选择有界执行与独立时序证据，是因为完整对象堆、多态与异步调度分析会显著扩大成本；单纯增加项目 API 白名单则不能解决值绑定问题。本轮不采用这两种方式。

## 验收

- 泛化回归覆盖参数重排、多用户、同 arity 重载、候选分派、递归、异常与 finally、错误值校验、前置/后置/忽略检查、循环零次、回退及缓存输出。
- JSON、中文 Markdown、SARIF 同时保留调用上下文、首包时序、截断标记和现有人工任务，不输出私有接口符号或源码值。
- 真实 javac 7 编译，成品 JAR 在真实 JDK 7 和 JDK 8 执行全部回归；三个目标只读复验，新 Codex 进程与直接 MCP 稳定报告相等。
- 比较 0.6.0 基线，逐项说明确定了什么、UNKNOWN 哪些变化及为什么；不把数量下降作为放宽判定的理由。
- 提交仅包含泛化实现、合成回归、设计与汇总，私有映射及目标报告留在本地；推送后核对远端提交。
