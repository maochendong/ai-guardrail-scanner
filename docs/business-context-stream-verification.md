# 0.7.0 调用上下文与流式时序验收

验证日期：2026-10-15。版本 `0.7.0`，规则集 `java-python-guardrail-v8`，报告结构 `1.6`。发行模块为 `compat/`。

## 本轮实现

| 能力 | 实现与边界 |
| --- | --- |
| Business 命名 | 五个原 Bank 生产类及对应测试改名为 Business；保留既有 `bank-*` 参数、配置及 `BANK-*` 规则 ID 兼容 |
| 跨函数身份 | 按唯一声明 ID 绑定函数，传递实际参数、返回值及共同控制证明；确定目标建立独立上下文，动态分派候选不授予确定证明 |
| 入口隔离 | 每个函数仍独立分析；某个调用点的可信身份不覆盖其他调用者；参数重排、相反判定分支和异常路径保守处理 |
| 首包时序 | 输出首个已映射本地释放与映射检查的相对顺序、同值关系、控制资格和失败语义；候选质量检查不等于安全 Guard |
| 截断处理 | 跨函数展开与独立入口分开计量；首包候选函数独立预算，路径取样不拼接不同路径的证据，截断明示 |
| 复核与报告 | JSON、中文 Markdown、SARIF 保留新事实及原有 UNKNOWN/人工事项；大报告按原有 MCP 文件交付协议验收 |

Java 使用可解析的声明身份与绑定确定性；Python 首期支持同文件、声明顺序明确的唯一同步模块函数，排除装饰器、默认参数、生成器等不确定绑定。任意虚分派、依赖注入、堆别名、异步回调和网络调度仍未完整建模。

本轮独立审查修复了相反 Guard 判定合并、caller 的 finally 待返回值污染 callee、catch/else 异常跳过本层 finally 三类误判，并补充预算截断后后续入口仍可访问的回归。新增实现与合成回归不以目标项目名称、接口名称或源码路径分支。

## 最终验收

- 使用真实 JDK `1.7.0_79` 的 javac 完成 `clean verify`。
- 35 个测试类、552 项 JUnit，在真实 JDK `1.7.0_79` 和 `1.8.0_40` 各通过一次；比 0.6.0 增加 103 项。原生测试使用最终 JAR 的生产类。
- 验收脚本 54 项测试通过，比 0.6.0 增加 21 项；包括三格式证据一致性与内联/文件交付正反例。
- 最终 JAR 含 1,048 个 class，最大 class major 为 51；旧 Bank 类已不存在。
- JAR SHA256：`19ee760b583d0c4c35d86bee5aa8bde8da80120512cd4d27067e36a51b6bd729`。
- 双 JVM 完成三项目 MCP 扫描、五个工具、三种报告、范围拒绝、错误恢复、取消和终态一致性验收；恢复并保留 0.6.0 的直接映射覆盖。
- 本地 Codex 已安装相同 SHA256 的 0.7.0 JAR，仅更新 scanner 的 JAR 路径并保留配置备份。新 Codex app-server 进程发现并实际调用五个 MCP 工具，三项目稳定报告与直接双 JVM 结果完全相同。
- 三个目标仓库的 HEAD、工作区状态及 tracked diff 摘要与本轮开始时一致；私有合同文件 SHA256 未变。

本轮曾发现复杂函数耗尽预算后遗漏后续入口的回退，以及验收脚本错误要求大报告内联返回的问题；均修复并从新目录重跑。最终统一证据采用 `scan-results/business-20261015/final-release-v2/`，早期中间运行不作为交付依据。

## 剩余事项如何处理

不能用调用点事实代替整条规则的结论。认证来源与参数传递关系可以由代码和合同确定，但具体部署的动态实现、资源所有权和拒绝行为仍需各自证据。首个本地 yield 的源码顺序可以确定，却不能直接证明网络已经送达或所有片段均受控。

| 项目 | 已补充的自动证据 | 仍可继续补齐的代码分析与映射 | 必须人工或运行验证 |
| --- | --- | --- | --- |
| CodeBuddy | 调用点保留未受信身份来源；逐位置记录输出时序未决 | 可审计的实现绑定、回调与 DTO 值流、会话主体到资源关系 | 认证主体一致性、会话/消息归属、控制的安全职责、失败和回退行为、知识资料权限范围 |
| wm-sales-atlas-analysis | 认证结果到服务实参的可信来源；确定私有调用与候选服务调用分开 | 依赖注入与虚分派、所有权断言的资源投影、流式片段绑定、真实检索入口 | 实际注入配置、会话并发绑定、工具授权范围、是否启用检索及其文档范围、真实输出时序 |
| 蒸馏小可乐 | 完整项目中先释放片段、后汇总检查的静态顺序 | 异步和生成器跨函数关系、片段与汇总值绑定、会话/缓存身份槽、混合检索权限映射 | 质量检查是否承担安全职责；向量/关键词/重排/缓存的授权与撤权一致性；拒绝、异常、超时和网络首包负测 |

人工事项要求交付证据：身份平台与应用负责人提供服务端信任链及覆盖规则；业务与数据权限负责人明确公开/私有/租户共享范围；安全控制负责人审查 Guard 的校验对象与失败语义；应用测试负责人完成跨用户、跨租户、撤权和失败路径负测。补映射和扩展分析属于研发工作，不转交业务人员口头背书。

完整技术方案见 [技术实现方案](technical-architecture.md)。本轮目标报告、真实 API 合同、详细源码位置及本机配置仅留本地；公开增量包含泛化实现、合成回归和汇总。
