# 0.8.0 外部语义复用与真实 API 规则包验收

验证日期：2026-10-16。发行模块 `compat/`，版本 `0.8.0`，规则集 `java-python-guardrail-v9`，报告结构 `1.7`。

## 实现范围

操作员显式提供的 API 合同现在可以同时服务业务专项和通用规则。扫描内只执行一次 `BusinessAnalysis`，`GenericSemanticAnalysis` 按语言、具体调用位置和模型值标签消费同义证据，不再单独解释一份合同。`generic` 可以加载合同，仍不输出 BANK 评估。

| 通用规则 | 复用的证据 | 不能据此证明 |
| --- | --- | --- |
| Java `AI-GUARD-002` / Python `AI-PY-005` | 同一模型输出值的 Guard 判定与本地释放关系 | 所有内容安全策略、未覆盖输出、实际网络首包 |
| Java `AI-L2-003` / Python `AI-PY-002` | 同一检索位置的文档权限、可信主体与资源约束 | 所有会话隔离、未映射数据源、部署权限系统 |

原有框架检查、违反和未覆盖 UNKNOWN 保留。数据出站不等同日志脱敏，工具能力授权不等同参数 schema 校验，不把专项整体结论覆盖到其他通用规则。新增记录保留 `semanticOrigin`、`semanticScope=MAPPED_LOCAL_SITES_ONLY` 和覆盖不完整标记；JSON、Markdown、SARIF 均可追溯到策略摘要和来源规则。对摘要过期或分析提前停止的范围保留未定位 UNKNOWN，不虚构调用位置。

位置明细存在上限；引擎另存有界的语言、模型值和处置代表证据，避免后出现的已知违反被截断隐藏。同一检索边界的身份与 ACL 代表配对保存。不同语言、模型与非模型值、不同调用位置不得相互借用结论。

## 真实规则包与原 9 项缺少映射

私有操作员规则包由 52 条合同、8 条接收者映射增加到 61 条合同、9 条接收者映射。原合同和三个已审查源码摘要保留，不修改目标应用，也不在引擎内加入项目名或私有 API 特判。

原 9 项中，8 项已定位真实业务边界并补充映射。它们仍需要值流、控制资格或场景证据，不能把“缺映射已解决”写成“安全已证明”。剩余 1 项为 wm-sales-atlas-analysis 的文档检索边界：扫描范围内未找到可确认的 RAG 文档检索实现，知识库标签和电子签署文档不构成检索证据；需确认实际部署与场景适用性。

- 双 JVM 完成三项目 MCP、五个工具、JSON/Markdown/SARIF、授权范围拒绝、错误恢复、取消及终态一致性验收。

- 三个目标仓库的 HEAD、工作区状态及 tracked diff 摘要与本轮开始时一致；扫描源码摘要与已审查映射一致，参数绑定失败及未完成适配文件均为零。

## 人工确认与研发补齐

必须人工确认的是代码之外的制度、部署和运行事实，并非所有 UNKNOWN：

| 事项 | 负责角色 | 应提交的证据 |
| --- | --- | --- |
| 场景适用性 | 产品、业务合规、应用架构负责人 | 预算/住房建议的业务定位；WM 是否实际部署 RAG 及纳入扫描的范围 |
| 身份与资源范围 | 身份平台、数据权限负责人 | 代理头清洗、主体/租户注入、匿名与兜底规则；文档/会话/缓存公开或受限分类及撤权策略 |
| Guard 与适当性职责 | 安全、业务及服务负责人 | 接受/拒绝定义、异常与降级政策、适当性矩阵与二次确认条件、生产依赖版本 |
| 工具和数据出站 | 工具平台、网络安全负责人 | 允许操作、参数、域名、凭据权限及实际网络控制配置 |
| 部署负测 | 测试、运维、安全验证人员 | 跨用户/租户、撤权、拒绝、异常、超时、取消、回退以及首次客户端可见输出；关联环境与版本 |

仍可由研发继续处理的缺口包括：DTO/JSON/集合字段值流、复合布尔判定、受限动态分派与 Python `self.method`、异步/生成器和流式片段关联、多控制角色及未覆盖路径预算。应先扩展分析和合成反例，再复扫；这些工作不转交业务人员口头确认。

完整私有 UNKNOWN、人工事项和研发清单保存在本轮本地验收目录，不提交公开仓库。人工确认不自动改变处置；调整范围、提升合同资格、完成运行测试各需独立依据。
