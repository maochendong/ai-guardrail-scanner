# 0.9.0 字段值流、复合判定与流式关联验收

版本 `0.9.0`，规则集 `java-python-guardrail-v10`，报告结构 `1.8`。本轮沿用外部 API 合同，不向引擎加入目标项目名或私有 API 特判。

## 实现与安全边界

| 能力 | 本轮支持 | 继续保留的边界 |
| --- | --- | --- |
| DTO 与 JSON 字段值流 | 源码明确的简单构造器、工厂、getter/setter；JDK Map 常量键；Python dict 写入/get；无同名本地模块冲突的受限常量 JSON | Lombok 生成实现、动态 JSON 内容、继承/初始化副作用、集合全部元素与已检查对象的关系 |
| 复合判定 | `decision.all` 描述同一次检查返回对象上的 1–8 个布尔条件；保留短路、否定、别名及提前返回事实 | OR 放行、遗漏条件、不同对象拼接、旧判定复用不能获得完整证明；控制资格和业务矩阵仍需独立依据 |
| 对象与证明失效 | 路径内对象版本、嵌套别名变更、检查快照、动态运算与未知调用后的失效 | 无界堆分析、反射、未解析分派和未知副作用继续 UNKNOWN |
| 流式关联 | 片段参与后续聚合值的源码依赖，报告 `checked-value-derived-from-release` | 派生关系不等于内容相同、全量流覆盖或首包已审核；候选/失败开放检查不会获得安全资格 |

显式运营合同优先于可选的字段简化。异常处理路径、候选转换资格和嵌套对象变化必须保留；不能为了减少 UNKNOWN 而删去可能的输出路径。独立审查和回归针对动态拼接副作用、内层字段修改、JSON 异常输出、同名本地模块遮蔽、候选转换后的字段访问等错误提升场景。

## 真实项目的逐位置变化

- **WM**：推荐结果的两处返回位置，在事实和适当性两条规则中共 4 条位置记录消除 `VALUE_PROJECTION_UNRESOLVED`。现在能定位包装对象的结果字段，集合元素与已检查对象的全量关系、身份可信来源和控制资格仍未证明。
- **RAG**：释放片段与后续聚合检查建立 2 条派生关系，分别为 `RELEASE_PRECEDES_MAPPED_CHECK` 和 `ORDER_UNRESOLVED`；两者均为 candidate/open。不能把“参与后续检查”描述为首包已受保护。同一流程另一身份位置新增 `STREAM_ELEMENT_UNRESOLVED`，更明确地保留未解析范围。
- **CodeBuddy**：一条数据出站位置记录不再带 `INTERPROCEDURAL_FLOW_BOUNDED`，但仍有局部值流和语义资格不足，因此继续 UNKNOWN。Lombok 生成访问器与动态 JSON 字段仍未解决。

上述共 7 个规则/位置分组发生变化，没有父级 UNKNOWN 转为 OBSERVED 或 VIOLATED。身份和 RAG 文档权限仍需继续结合可信主体、同一资源范围和全部相关路径，不把字段能力的改善推断为权限控制已完成。

完整记录分别为本地本轮目录下的 `unknown-review.md/json`、`manual-review.md/json`、`technical-followups.md/json` 和 `comparison.json`。人工报告动作按规则、动作及负责人合并为 16 组，另列 8 项业务/部署事项；研发动作合并为 123 组。这些是工作项分组，既不是独立漏洞数，也不与 84 条 UNKNOWN 一一对应。

## 人工确认与研发后续

必须人工确认的是代码之外的范围、资格和运行事实：场景适用性；身份与租户的可信注入；文档、会话和缓存的公开/受限分类及撤权；Guard 的职责、接受/拒绝和失败策略；适当性矩阵与二次确认；工具/出站白名单；部署中的异常、超时、跨租户、撤权及实际客户端首包负测。负责角色分别包括业务/合规、身份与数据权限平台、安全、工具平台和测试运维。

生成访问器、动态 JSON 字段、集合全元素证明、Python 动态调用和异步关系是研发能力缺口，不能用人工口头确认替代。完整逐位置 UNKNOWN、人工事项和研发清单保留在本地验收目录，公开仓库只保留脱敏汇总。
